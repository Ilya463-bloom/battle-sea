# Sea Battle

Classic Battleship for two players sharing one device, drawn as if sketched with a
blue pen in a squared notebook. No login, no backend, no persistence — a game
lives entirely in one browser session.

## Rules

- Two 10×10 grids, columns `A`–`J`, rows `1`–`10`.
- Fleet: 1 × four-deck, 2 × three-deck, 3 × two-deck, 4 × one-deck.
- Ships are straight and may never touch, not even diagonally.
- A hit keeps the turn; a miss passes the device to the other player.
- Sinking a ship automatically marks the water around it — those cells can no
  longer be shot at.
- The game ends when one fleet is completely destroyed.

## Flow

```
intro → player 1 places → handoff → player 2 places → handoff → battle → result → intro
```

The two handoff screens exist so neither player sees the other's fleet while it is
being arranged. During the battle a player only ever sees the opponent's waters,
never their own board.

## Placing ships

- Drag a ship from the dock onto the grid.
- `⟳ Across / Down` sets the orientation of ships still in the dock.
- Tap a ship already on the grid to turn it; drag it to move it; drag it off the
  grid to send it back to the dock.
- Invalid drops are shown in red pen and are refused.
- `⚄ Random` fills the whole grid with a legal layout, `✕ Clear` empties it.

## Stack

Solid.js · TypeScript · Tailwind CSS v4 · Vite · Capacitor (Android)

## Development

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # typecheck + production bundle into dist/
npm run preview    # serve the built bundle
npm run check      # typecheck + both smoke tests
```

Two headless checks run without a browser and without a test framework; both exit
non-zero on failure.

- `npm run check:logic` — `scripts/logic-check.ts` drives the rules engine: 500
  random layouts, the no-touching rules, a full game, turn handover, replay reset.
- `npm run check:render` — `scripts/render-check.ts` renders every screen through
  Solid's server renderer and asserts on the resulting markup. It proves each
  screen mounts without throwing and that the text a player must see is there. It
  cannot judge how anything looks — that still needs a pair of eyes.

## Layout

```
src/
  game/          rules engine, framework-agnostic
    constants.ts   board size, labels, fleet pool
    types.ts
    fleet.ts       geometry, placement validation, random layouts
    state.ts       Solid store + all game actions
  components/
    Board.tsx      grid with labels, ship shapes, hit/miss marks
  screens/         intro · placement · handoff · battle · result
  platform/
    native.ts      Capacitor bridge, no-ops in a plain browser
scripts/
  logic-check.ts   rules-engine smoke test
  render-check.ts  server-render smoke test for every screen
```

`src/game` holds the rules and depends only on the Solid store, so they can be
tested — and reused — without any UI.

## Android

The native project is generated by Capacitor and is not in the repository yet.
Requires Android Studio, JDK 21 and the Android SDK.

```bash
npm run android:add     # once — generates android/
npm run android:open    # build + sync + open in Android Studio
npm run android:run     # build + sync + run on a device or emulator
```

`npm run android:sync` rebuilds the web bundle and copies it into the native
project — run it after every change to `src/`.

Before publishing, change `appId` in `capacitor.config.ts`; `com.battlesea.game`
is a placeholder.

### What is already in place

- `base: './'` in `vite.config.ts`, so the bundle loads from `file://`.
- Fonts are bundled locally (`@fontsource`, latin subset only) — the app works
  fully offline. The whole `dist/` is about 330 KB.
- `src/platform/native.ts` wires up the status bar, splash screen, haptics on
  every shot, and the Android hardware back button. All of it is inert on the web,
  so there is a single build for both targets.
- Safe-area padding for notches and gesture bars.
- Ship dragging uses pointer events with `touch-action: none`, so it behaves the
  same with a mouse and with a finger.
